# Тексты для площадок

Всё, что площадки просят при выпуске, — здесь, чтобы при открытой форме на
сайте ничего не приходилось выискивать в общих документах. Порядок выпуска по
шагам — [docs/RELEASING.md](../../docs/RELEASING.md), что где опубликовано —
[docs/platforms.md](../../docs/platforms.md).

```
page.md                   страница мода — ОДНА на Thunderstore, Hexium и Nexus
short-description.txt     строка до 250 знаков: манифест Thunderstore и summary на Nexus
pages.py                  page.md → nexus/description.bbcode; README для архива
gallery.md                скриншоты: порядок, подписи, где какой стоит
thunderstore/upload.md    что загружать и как обновлять; так же у каждой площадки
hexium/upload.md
nexus/
  upload.md
  description.bbcode      описание на Nexus; собирается, руками не править
  images.json             файл из media/ → адрес картинки в галерее Nexus
  live-description.bbcode то, что стояло на Nexus до 1.3.0, — для сверки
```

## Правило одно

**Текст правится только в `page.md`.** Потом:

```
python store/pages.py
```

Он пересоберёт `nexus/description.bbcode` и скажет, у каких картинок нет
адреса. README для Thunderstore и Hexium собирает `package.py` из того же
`page.md`, подставляя адреса картинок из `images.json`; без адреса он откажется
собирать — ссылка `media/…` на площадке стала бы битой картинкой.

Почему так. До 1.3.0 текстов было три: `pack/README.md` для Thunderstore и
Hexium, описание на Nexus, набранное прямо в форме на сайте, и README
репозитория. За три выпуска они разошлись: на Nexus не было ни карточки
предмета, ни закреплённого плана, в разделе настроек не хватало половины
ключей, зато осталась ссылка на GitHub, которую с других площадок уже убрали.
Текст, живущий только в веб-форме, к следующему выпуску пишется по памяти и
каждый раз чуть иначе.

## Разметка page.md

Узкая намеренно — ровно то, что переводится в BBCode без потерь:

- заголовки `#` и `##` (перед каждым `##` на Nexus встаёт черта `[line]`);
- абзацы, списки `-` и `1.`, **жирный**, `код` (на Nexus — жирным), ссылки;
- картинки — отдельной строкой, `![подпись](media/файл.png)`; на Nexus их
  нет, там галерея;
- одна таблица: настройки, четыре столбца «раздел · ключ · по умолчанию ·
  смысл». На Nexus она становится блоком `[code]`, сгруппированным по
  разделам, как в самом `.cfg`.

Чего-то сверх этого (вложенные списки, `###`, HTML) `pages.py` не знает: либо
научить его, либо обойтись.
